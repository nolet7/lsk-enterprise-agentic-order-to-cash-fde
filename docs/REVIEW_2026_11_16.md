# Senior FDE engineering review — 2026-11-16
## Method
Inspected repository head for production, local commerce domain, agent, OIDC, pilot approvals, CI, Terraform and Helm, plus latest GitHub Actions. Current project is a **synthetic portfolio lab**, not an ASR Group deployment.
## Critical findings and remedies
1. Previous production chart allowed demo authentication by configuration omission and API defaulted to demo. Fail closed in pilot/production with startup guard and explicit AUTH_MODE=oidc.
2. Previous draft confirmation loaded draft before locking it. Explicit PostgreSQL row lock before decision reduces race between simultaneous submissions with distinct idempotency keys; still needs actual PG concurrency test and durable ERP reconciliation.
3. Previous API liveness did not establish DB readiness. Introduce /ready that queries DB and keep /health liveness-only.
4. Previous image ran as root despite non-root Helm pod settings; set explicit UID/GID in container image and retain Kubernetes restrictions. Confirm writable artifacts in production and model provider failure path.
5. Critical unclosed: AI factual grounding is only lexical policy ranking, not vector RAG; no networked authenticated MCP server; no actual production ERP/CRM/WMS/Billing service adapters end-to-end.
6. Critical unclosed: production chart lacks managed secret hydration, TLS ingress/WAF, protected egress, deployment secret rotation, configured model API endpoint, migration job, Argo Rollouts and release admission evidence. Production secrets/real model provider configuration should never be committed.
7. Multi-tenant isolation is scoped in ORM queries but no Postgres row-level security; CSR identity is not bound to selected customer and CSR ticket creation is not implemented as an authorized cross-account workflow.
8. Cost, p95, recovery RPO/RTO and business ROI unmeasured. CI passing cannot establish enterprise readiness.
